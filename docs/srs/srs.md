## 1. Введение

Документ описывает требования к настольному приложению Liquid Ping, которое проверяет доступность сетевых узлов и показывает подробную информацию о них в интерфейсе в стиле «liquid glass». Разделы 1–2 задают контекст, раздел 3 содержит требования, раздел 4 — план их проверки.

### 1.1 Назначение документа

Документ определяет, **ЧТО** должна делать система Liquid Ping, но не то, как она будет реализована. Он предназначен для разработчика (он же заказчик и тестировщик в учебном проекте), преподавателя и всех, кто захочет использовать или развивать проект после публикации на GitHub. Связанные документы: SDD и ADR (создаются в последующих лабораторных работах).

### 1.2 Область применения продукта

Liquid Ping — десктопное приложение для Windows 11, которое в реальном времени показывает, доступны ли нужные сайты и сервисы, с какой задержкой и потерями они отвечают, и позволяет по запросу просканировать открытые TCP-порты выбранного узла. Приложение рассчитано на любого пользователя: от обычного человека, который хочет понять, «лежит сервис или проблема у него дома», до начинающего администратора. Из коробки включён набор популярных узлов (Yandex, Google, Steam, Minsktrans, Ozon, Wildberries), но пользователь может составить собственный список.

## 2. Обзор продукта

### 2.1 Перспектива продукта

Liquid Ping — новый самостоятельный продукт, не зависящий от других систем компании. Он работает локально на компьютере пользователя и обращается только к узлам из его списка. Внешние зависимости: сетевой стек Windows, DNS-резолвер ОС, службы уведомлений Windows. Приложение распространяется как открытое ПО через GitHub.

```
Пользователь  ──►  Liquid Ping  ──►  Сетевой стек Windows  ──►  Узлы в интернете / локальной сети
                         │
                         └──►  Файлы настроек и логов (%AppData%)
```

### 2.2 Функции продукта

1. Мониторинг доступности узлов по ICMP, TCP и HTTP с отображением статуса, задержки, потерь и IP-адреса.
2. Управление списком узлов (набор по умолчанию, добавление, изменение, удаление).
3. Сканирование открытых TCP-портов выбранного узла по запросу.
4. Обнаружение доступных хостов в локальной сети по запросу.
5. История и график задержки, учёт трафика проверок (за сеанс).
6. Уведомления об изменении статуса.
7. Настройки: интервалы, тайм-ауты, тема, язык, уведомления.

### 2.3 Ограничения продукта

- Платформа: Windows 11 (22H2 и новее), архитектура x64.
- Технологии: C#, WPF, актуальная LTS-версия .NET.
- Потребление оперативной памяти — не более 1 ГБ.
- Опрос узлов должен быть асинхронным.
- Приложение должно работать без прав администратора.

### 2.4 Характеристики пользователей

| Роль                               | Описание                                                       | Что важно                                              |
|------------------------------------|----------------------------------------------------------------|--------------------------------------------------------|
| Обычный пользователь               | Хочет быстро понять, доступен ли сайт или сервис               | Простой интерфейс, понятные статусы, минимум кликов    |
| Начинающий администратор / студент | Проверяет доступность и открытые порты своих или учебных узлов | Точные метрики (задержка, потери), сканирование портов |

Пользователи не обязаны знать сетевые протоколы. Специальных навыков не требуется.

### 2.5 Допущения и зависимости

- У пользователя есть сетевое подключение, иначе все узлы показываются как недоступные (см. REQ-REL-003).
- Целевые узлы могут блокировать ICMP, поэтому статус узла определяется комбинацией ICMP, TCP и HTTP (см. REQ-FUNC-005).
- Размытие фона обеспечивается средствами Windows 11 (DWM backdrop); на других ОС стиль может быть недоступен (см. REQ-INT-005).
- Пользователь сам отвечает за то, какие узлы он проверяет и сканирует.

### 3.5 Проектирование и реализация

#### 3.5.1 Установка

Приложение поставляется как переносимый архив (self-contained, без установки) в разделе Releases на GitHub. Полноценный установщик (Inno Setup или MSIX) не входит в версию 1.0 и может быть добавлен позже без изменения остальных требований.

#### 3.5.2 Сборка и поставка

Сборка выполняется командой `dotnet publish` (self-contained, x64). Сборка из исходников должна воспроизводиться по инструкции в README.

#### 3.5.3 Распределение

Не применимо: приложение работает локально на одном компьютере.

#### 3.5.4 Сопровождаемость

Код разделяется на слой интерфейса (MVVM) и слой сетевой логики, который можно тестировать без UI. Для сетевой логики пишутся модульные тесты.

#### 3.5.5 Повторное использование

Сетевая логика (проверки и сканер портов) оформляется отдельной библиотекой без зависимостей от WPF.

#### 3.5.6 Переносимость

Поддерживается только Windows 11 x64. Windows 10, Linux и macOS не поддерживаются в версии 1.0.

#### 3.5.7 Стоимость

Проект не имеет бюджета: используются только бесплатные инструменты и библиотеки.

#### 3.5.8 Сроки

| Фаза | Ключевой этап                                                                           | Срок       | Зависимости                        | Критерии готовности |
|:-----|:----------------------------------------------------------------------------------------|:-----------|:-----------------------------------|:--------------------|
| 1    | Предоставление SRS на защиту                                                            | 2026-10-07 | Полностью оформленный документ SRS | 2%                  |
| 2    | Повторное предоставление SRS на защиту после обратной связи и последующих корректировок | 3%         |

#### 3.5.9 Доказательство концепции

Перед полной реализацией нужен небольшой прототип, подтверждающий, что эффект liquid glass (размытие фона) работает в WPF на Windows 11 и укладывается в лимит памяти и производительности (REQ-INT-001, REQ-PERF-001).

#### 3.5.10 Управление изменениями

Работа ведётся в ветках git, версии нумеруются по SemVer, изменения фиксируются в `CHANGELOG.md`.

### 3.6 ИИ/МО

Не применимо: продукт не содержит компонентов машинного обучения.
