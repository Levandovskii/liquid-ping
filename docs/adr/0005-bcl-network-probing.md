# ADR-0005: Сетевые проверки и сканирование средствами BCL и ARP-таблицы Windows

## Контекст и постановка задачи

Приложение выполняет ICMP-, TCP- и HTTP-проверки, сканирует TCP-порты и находит хосты в локальной сети. SRS требует работу без прав администратора (REQ-SEC-001), использование только сетевого стека ОС без драйверов и сторонних служб (REQ-INT-006), совместимость лицензий с MIT (REQ-COMP-001) и ограничивает сканирование TCP (SYN/stealth и UDP вне рамок).

Вопрос: какими средствами выполнять проверки и сканирование, чтобы удовлетворить эти ограничения?

## Драйверы решения

* Работа без прав администратора и без драйверов (REQ-SEC-001, REQ-INT-006)
* Совместимость лицензий (REQ-COMP-001)
* Простота распространения: только переносимый архив
* Достаточность для функций SRS (REQ-FUNC-003…005, 010, 020)
* Безопасность: не вводить возможности, выходящие за границы продукта

## Рассмотренные варианты

* Только BCL: `Ping`, `Socket`/`TcpClient` (connect-скан), `HttpClient`, `NetworkInterface`, плюс чтение ARP-таблицы Windows через вызов `GetIpNetTable`
* Сырые сокеты или библиотека захвата пакетов (например, SharpPcap с Npcap) для SYN-скана
* Обёртка над внешними утилитами (`nmap`, `ping.exe`)

## Итог решения

Выбранный вариант: «Только BCL и ARP-таблица Windows», потому что он единственный выполняет все ограничения: работает под обычной учётной записью, не требует драйверов и внешних программ и использует только штатные средства ОС.

Таблица ARP Windows (`GetIpNetTable`) используется не только для чтения MAC-адресов ответивших узлов, но и для пассивного обнаружения активных устройств подсети, которые игнорируют ICMP-пакеты («тихие» хосты). Сопоставление MAC-адреса с производителем (OUI) выполняется строго локально и автономно по встроенной базе (см. ADR-0006), поэтому REQ-SEC-003 и SYS-NFR-005 соблюдаются: телеметрии и сторонних сетевых запросов нет.

### Последствия

* Хорошо, потому что приложение запускается без прав администратора и без установки драйверов.
* Хорошо, потому что нет лицензионных рисков и внешних бинарных зависимостей.
* Хорошо, потому что реализация простая и тестируется подменой `IProbe`.
* Хорошо, потому что устройства, блокирующие ICMP, обнаруживаются по записям ARP-таблицы и отображаются в результатах.
* Хорошо, потому что определение производителя по MAC-адресу полностью локальное и не создаёт сетевых запросов.
* Плохо, потому что доступно только connect-сканирование: состояния портов определяются по ответу соединения (открыт, отказ, таймаут), без SYN-скана.
* Плохо, потому что часть узлов блокирует ICMP, поэтому статус опирается на комбинацию ICMP, TCP и HTTP.
* Плохо, потому что MAC-адрес доступен только для устройств того же сегмента сети и только после обращения к ним.
* Плохо, потому что запись ARP может оставаться в кэше после отключения устройства, а для хостов, найденных только по ARP, задержка не измеряется.

### Подтверждение

Приложение запускается и все функции работают под обычной учётной записью без повышения прав (тест по REQ-SEC-001). Установка в чистой системе не требует драйверов (проверка релизного чек-листа). Автоматическая проверка списка зависимостей на отсутствие пакетов захвата пакетов. Тест обнаружения: устройство, не отвечающее на ICMP, присутствует в результатах по записи ARP. Сетевой анализ показывает отсутствие обращений при определении производителя по MAC-адресу.

## Плюсы и минусы вариантов

### Только BCL и ARP-таблица Windows

* Хорошо, потому что работает без прав администратора.
* Хорошо, потому что нет внешних зависимостей и лицензионных ограничений.
* Нейтрально, потому что вызов `GetIpNetTable` требует небольшого P/Invoke-кода.
* Плохо, потому что нет SYN-сканирования и других «глубоких» методов.

### Сырые сокеты или библиотека захвата пакетов

* Хорошо, потому что возможны SYN-скан и более точное определение состояния портов.
* Плохо, потому что обычно нужны права администратора и драйвер захвата.
* Плохо, потому что лицензия драйвера Npcap ограничивает распространение вместе с приложением.
* Плохо, потому что выходит за границы продукта (SYN/stealth в Out-of-scope).

### Обёртка над внешними утилитами

* Хорошо, потому что готовая функциональность.
* Плохо, потому что внешний бинарник нужно поставлять и сопровождать; лицензия Nmap накладывает ограничения на распространение.
* Плохо, потому что разбор текстового вывода хрупок и зависит от локали.

## Дополнительная информация

Связанные требования: REQ-SEC-001, 002, REQ-INT-006, REQ-FUNC-003…005, 010, 020, REQ-COMP-001. Представления SDD: 001-context, 005-interface, 007-algorithm. Решение использовать ARP-таблицу для «тихих» хостов принято по итогам согласования с заказчиком (SDD 5.4, SYS-FUNC-015).
