# ADR-0001: UI-платформа — WPF на текущей LTS-версии .NET

## Контекст и постановка задачи

LiquidPing — десктопное приложение для Windows 11 с интерфейсом в стиле liquid glass (SRS 2.3, REQ-INT-001). Заказчик сформулировал технологическое ограничение: C# и WPF. Нужно зафиксировать, на какой UI-платформе и среде выполнения строится приложение и не лучше ли для него альтернативы.

Вопрос: какой UI-фреймворк и какую версию .NET использовать, чтобы выполнить ограничения SRS (Windows 11, не более 1 ГБ памяти, без прав администратора)?

## Драйверы решения

* Требование заказчика: C# и WPF (критерий отсечения, k.o.)
* Потребление памяти не более 1 ГБ (REQ-PERF-001)
* Поддержка только Windows 11, x64 (SRS 2.3, 3.5.6)
* Зрелость фреймворка и наличие документации для одного разработчика
* Возможность получить эффект размытия фона (REQ-INT-001)
* Долгосрочная поддержка среды выполнения (LTS)

## Рассмотренные варианты

* WPF на текущей LTS-версии .NET
* WinUI 3 (Windows App SDK)
* Avalonia UI
* Windows Forms

## Итог решения

Выбранный вариант: «WPF на текущей LTS-версии .NET» (на момент проектирования `net10.0-windows`), потому что это единственный вариант, удовлетворяющий критерию отсечения (требование заказчика), и при этом он покрывает остальные драйверы.

### Последствия

* Хорошо, потому что требование заказчика выполнено без обсуждения исключений.
* Хорошо, потому что у WPF зрелая экосистема, подробная документация и хорошая поддержка MVVM и привязки данных.
* Хорошо, потому что LTS-версия .NET даёт предсказуемый срок поддержки.
* Плохо, потому что в WPF нет встроенных материалов Mica и Acrylic, их нужно подключать через системные вызовы (см. ADR-0002).
* Плохо, потому что WPF работает только в Windows; это соответствует границам продукта (Linux и macOS вне рамок), но закрывает путь к переносимости.

### Подтверждение

Проекты решения указывают `net10.0-windows` в `*.csproj` (проверка на code review). Прототип liquid glass по SRS 3.5.9 подтверждает, что платформа даёт нужный эффект и укладывается в лимит памяти.

## Плюсы и минусы вариантов

### WPF на текущей LTS-версии .NET

* Хорошо, потому что соответствует требованию заказчика.
* Хорошо, потому что зрелый и хорошо документированный фреймворк.
* Нейтрально, потому что сборка self-contained добавляет к размеру поставки среду выполнения.
* Плохо, потому что эффекты Fluent-дизайна требуют ручной интеграции.

### WinUI 3 (Windows App SDK)

* Хорошо, потому что материалы Mica и Acrylic доступны из коробки.
* Плохо, потому что нарушает критерий отсечения (заказчик требует WPF).
* Плохо, потому что более тяжёлая модель поставки (Windows App SDK) и меньший опыт работы.

### Avalonia UI

* Хорошо, потому что кроссплатформенность и гибкая стилизация.
* Плохо, потому что нарушает критерий отсечения, а кроссплатформенность не нужна (Windows 11 only).

### Windows Forms

* Хорошо, потому что простой и лёгкий фреймворк.
* Плохо, потому что нарушает критерий отсечения и плохо подходит для полупрозрачных стеклянных панелей.

## Дополнительная информация

Связанные требования: SRS 2.3, 3.5.6, REQ-INT-001, REQ-PERF-001. Представления SDD: 002-composition, 013-dependency. Решение пересматривается, если заказчик снимет ограничение на WPF.
