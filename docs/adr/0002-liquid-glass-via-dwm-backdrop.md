# ADR-0002: Эффект liquid glass через системный backdrop DWM и полупрозрачные панели

## Контекст и постановка задачи

Заказчик требует стиль liquid glass: полупрозрачные скруглённые панели с размытием фона под ними (REQ-INT-001). Должна быть читаемая типографика в обеих темах (REQ-INT-003) и запасной вариант, если эффекты отключены (REQ-INT-005). Потребление памяти ограничено (REQ-PERF-001), интерфейс должен оставаться отзывчивым (REQ-PERF-002).

Вопрос: как в WPF на Windows 11 получить размытие фона с минимальной нагрузкой и без хрупких обходных путей?

## Драйверы решения

* Визуальный результат: размытый фон под панелями (REQ-INT-001)
* Низкая нагрузка на CPU, GPU и память (REQ-PERF-001, REQ-PERF-002)
* Минимум сторонних зависимостей (REQ-COMP-001)
* Корректная работа запасного варианта без эффектов (REQ-INT-005)
* Читаемость текста на стеклянных панелях (REQ-INT-003)

## Рассмотренные варианты

* Системный backdrop окна (Mica/Acrylic) через DWM плюс полупрозрачные панели
* Библиотека Fluent-стилизации для WPF (например, WPF-UI)
* Собственное размытие внутри приложения (`BlurEffect` или шейдер поверх снимка фона)

## Итог решения

Выбранный вариант: «Системный backdrop окна через DWM плюс полупрозрачные панели», потому что размытие выполняет сам Windows при композиции окон, что даёт минимальную нагрузку без сторонних зависимостей, а внешний вид стеклянных панелей достигается полупрозрачными кистями с тонировкой по теме.

### Последствия

* Хорошо, потому что размытие рисует DWM, а приложение не расходует память и CPU на обработку изображений.
* Хорошо, потому что без сторонних библиотек остаётся простой список зависимостей.
* Хорошо, потому что запасной вариант прост: при отключённых эффектах задаётся непрозрачная заливка панелей.
* Плохо, потому что размытие применяется ко всему окну, а «стеклянность» отдельных панелей имитируется полупрозрачной тонировкой, а не независимым размытием каждой панели.
* Плохо, потому что нужен код-обёртка над `DwmSetWindowAttribute` и настройка прозрачности окна WPF, которую придётся сопровождать.
* Плохо, потому что эффект доступен только в Windows 11 22H2 и новее.

### Подтверждение

Прототип по SRS 3.5.9: окно WPF с системным фоном, измерение памяти и отзывчивости. Ручной тест с отключёнными эффектами прозрачности Windows (REQ-INT-005) и проверка контраста текста в обеих темах (REQ-INT-003).

## Плюсы и минусы вариантов

### Системный backdrop окна через DWM

* Хорошо, потому что низкая нагрузка и нативный вид Windows 11.
* Хорошо, потому что нет зависимостей.
* Нейтрально, потому что вид зависит от обоев и настроек системы.
* Плохо, потому что размытие нельзя задать отдельно для каждой панели.

### Библиотека Fluent-стилизации (например, WPF-UI)

* Хорошо, потому что готовые стили и поддержка Mica/Acrylic.
* Нейтрально, потому что внутри всё равно используется системный backdrop.
* Плохо, потому что добавляет зависимость и навязывает собственный стиль, который придётся переопределять под liquid glass.

### Собственное размытие внутри приложения

* Хорошо, потому что независимое размытие для каждой панели.
* Плохо, потому что требует получения снимка содержимого под окном, что ненадёжно и дорого по ресурсам.
* Плохо, потому что рискует нарушить REQ-PERF-001 и REQ-PERF-002.

## Дополнительная информация

Связанные требования: REQ-INT-001, 003, 005, REQ-PERF-001, 002. Представления SDD: 002-composition, 005-interface. Если прототип покажет неприемлемый результат, решение пересматривается в пользу библиотеки Fluent-стилизации.
